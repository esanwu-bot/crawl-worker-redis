# Agent 版 测试指南

面向 `agentVersion/`（Agent Orchestrator + Workbench UI + Crawler Engine）的**可复现测试手册**。

目标：3 条命令内跑通「意图 → 计划 → 审批 → 播种 → 采集 → 落库」，并能快速定位本次修复过的 2 类问题：

1. HTTP 响应被日志污染，前端报 `Expected ',' or ']' ... position 5`
2. 任务层误连本地老版本 Redis，`XADD tasks 失败`

---

## 1. 环境要求

| 项 | 要求 | 检查命令 |
|---|---|---|
| PHP | >= 8.1（实测 8.2.9 NTS x64） | `php -v` |
| 扩展 | `redis` `pdo_mysql` `curl` `openssl` `mbstring` | `php -m \| findstr /I "redis pdo_mysql curl openssl mbstring"` |
| Redis | **>= 5.0（必须支持 Streams）**，实测远程 6.2.22 | `redis-cli -h <host> -p <port> -a <auth> info server \| findstr redis_version` |
| MySQL | 结果层，库名默认 `shikues_crawler` | `php bin/init_db.php` |
| Composer | 安装 Neuron v3 Harness（`neuron-core/neuron-ai`） | `composer install` |

> `NeuronAI\Agent\Agent` 类是否存在，决定走 `NeuronPlanner`（快）还是 `LlmPlanner`（curl 直连，慢）。

## 2. 配置

### 2.1 env 加载优先级

```
真实 shell 环境变量  >  agentVersion/.env  >  仓库根 .env.local
```

- `agentVersion/.env`：应用自身配置（LLM Provider / Key / BaseURL / Model），已 gitignore
- 仓库根 `.env.local`：本机/远程**连接项兜底**（Redis / MySQL），已 gitignore

> 连接项写在仓库根 `.env.local`，`agentVersion` 会自动兜底读取；命令行注入始终最高优先级。

### 2.2 相关变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `CW_REDIS_HOST` | `127.0.0.1` | 任务层 Redis 地址 |
| `CW_REDIS_PORT` | `6379` | |
| `CW_REDIS_AUTH` | 空 | 无密码留空 |
| `CW_REDIS_PREFIX` | `cw:shikues:` | key 前缀 |
| `CW_MYSQL_*` | `127.0.0.1/root/root/shikues_crawler` | 结果层 |
| `CW_AGENT_LLM_PROVIDER` / `_KEY` / `_BASE_URL` / `_MODEL` | - | Planner 用的 LLM |
| `CW_MAX_PAGES` | `3` | 每系列最多抓多少页 |

### 2.3 验证配置（**必做**）

```bash
cd agentVersion
php -r "$c=require 'config/config.php'; $r=$c['redis']; $r['auth']=$r['auth']===''?'(empty)':'(set)'; echo json_encode($r,JSON_PRETTY_PRINT|JSON_UNESCAPED_SLASHES),PHP_EOL;"
```

期望输出 `"host"` 为**远程地址**（否则就是 §6 的「连错 Redis」故障）。

## 3. 启动

### 3.1 初始化数据表（首次）

```bash
php bin/init_db.php
```

### 3.2 启动 HTTP + Workbench UI

方式 A —— 官方包装命令：

```bash
php bin/orchestrator.php serve --host 127.0.0.1 --port 8787
```

方式 B —— 直接起内置服务器（**推荐：可显式放宽执行时限**）：

```bash
php -d max_execution_time=300 -S 127.0.0.1:8787 -t ui bin/orchestrator-router.php
```

> ⚠️ `bin/orchestrator.php serve` 内部用 `passthru` 起 `php -S`，**不会**把父进程的 `-d` 透传给子进程。
> 需要更长时限时，请用方式 B，或直接在 `php.ini` 里调大 `max_execution_time`。
> 原因见 §6「30 秒超时」。

打开 http://127.0.0.1:8787/ 即为 Workbench UI。

### 3.3 启动 Worker（常驻消费者）

```bash
# 常驻（推荐，配合 supervisor / 多开）
php bin/worker.php --idle-rounds 0

# 空转 8 轮后自动退出（适合一次性验证）
php bin/worker.php --idle-rounds 8

# 自定义消费名（同组内须全局唯一）
php bin/worker.php --name w1
```

> ⚠️ Worker 是长驻进程，**修改 Redis / MySQL 配置后必须重启 Worker**，否则它仍连着旧实例。

## 5. 端到端测试

### 5.1 CLI（不依赖 UI，最快闭环）

```bash
# 自动审批，一次跑完 plan→seed→crawl→done
php bin/orchestrator.php run --intent "采集快恢复二极管 2 页" --approve

# 只出计划，等人审批
php bin/orchestrator.php run --intent "采集快恢复二极管 2 页"

# 审批 + 查详情 + 控制
php bin/orchestrator.php approve --id <jobId>
php bin/orchestrator.php status  --id <jobId>
php bin/orchestrator.php control --id <jobId> --action pause|resume|cancel
```

### 5.2 HTTP（Workbench 同款链路）

```bash
# 1) 创建任务（不传 id 会自动生成）
curl -s -X POST http://127.0.0.1:8787/api/jobs \
  -H "Content-Type: application/json" \
  --data "{\"intent\":\"采集快恢复二极管 2 页\",\"approve\":false}"

# 2) 审批继续
curl -s -X POST http://127.0.0.1:8787/api/jobs/<jobId>/approve

# 3) 任务详情 / 死信
curl -s http://127.0.0.1:8787/api/jobs/<jobId>
curl -s http://127.0.0.1:8787/api/dead
```

创建任务期望返回：

```json
{"job_id":"...","status":"pending_approval",
 "plan":{"type_ids":[6],"target_pages":2,"requires_approval":true,
         "metadata":{"planner":"neuron","model":"..."}}}
```

### 5.3 校验落库结果

```bash
php bin/stats.php --recent 5
```

## 6. 验收检查点

| # | 检查项 | 期望 | 命令 / 位置 |
|---|---|---|---|
| 1 | 响应是纯 JSON | 首字符 `{`，无 `INFO` 前缀 | `curl -s .../api/stats` |
| 2 | Redis 指向正确实例 | host = 远程地址、版本 6.2.x | §2.3 |
| 3 | 计划由 LLM 产出 | `plan.metadata.planner == "neuron"` | §5.2 响应体 |
| 4 | 任务入队成功 | `xlen` 增长、无 `XADD tasks 失败` | `php bin/stats.php` |
| 5 | Worker 消费 | `product_models` 增长、心跳出现 | `php bin/stats.php`、`/api/workers` |

纯 JSON 自检（PowerShell）：

```powershell
$b = curl.exe -s http://127.0.0.1:8787/api/stats
if ($b[0] -eq '{') { "OK pure JSON" } else { "BAD, first char = $($b[0])" }
```

## 8. 常见故障对照表

| 现象 | 根因 | 处理 |
|---|---|---|
| 前端报 `Expected ',' or ']' ... position 5` | `Logger` 把 `INFO` 直接 `echo` 进响应体，污染了 JSON | 已修复：router 顶部 `ob_start()` + `Logger` 仅 CLI 输出到 stdout，HTTP 进程只写文件。确认这 3 个文件为最新：`bin/orchestrator-router.php`、`src/Logger.php`、`config/config.php` |
| `RuntimeException: XADD tasks 失败` | 任务层连到了 **Redis < 5.0**（无 Streams）或连错实例 | 跑 §2.3 确认 host；修好后**同时重启 HTTP 服务与 Worker** |
| `HTTP 429 ... inference exceeds tpm/rpm limit` | LLM 触发限流，`NeuronPlanner` 自动回退 `LlmPlanner` | 稍后重试 / 降低并发 / 换模型；仅为降级告警，不是崩溃 |
| `Maximum execution time of 30 seconds exceeded in .../LlmPlanner.php` | `php -S` 默认 `max_execution_time=30`；回退到慢的 `LlmPlanner` 时请求超 30s | 用 §3.2 方式 B（`-d max_execution_time=300`）或调大 `php.ini` |
| `Duplicate entry 'xxx' for key 'PRIMARY'` | 复用了同一个 `job_id` | 换新 id；不传 `id` 会自动生成 |
| 改完配置仍连旧 Redis | Worker / HTTP 进程未重启 | 重启 §3.2 与 §3.3 |

## 9. 重置（重新演示）

```bash
# 清空 Redis 任务层（任务流/死信/统计/游标/重试计数），不动 MySQL
php bin/reset.php
```

> 如需连 MySQL 结果一起重置，配合 `php bin/seed.php --force` 全量重采。
